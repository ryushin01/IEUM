# 접근성 점검 (KWCAG 2.2)

33개 검사항목을 웹 화면의 코드와 화면으로 직접 점검한 기록입니다. 앱의 Flutter 피드, DM, 하단 메뉴는 이 표에 포함되지 않으며, 위젯 테스트로 조작 영역, 글자 대비, 낭독 이름만 확인했습니다. Flutter 피드의 사진 위 글자는 웹과 같은 막과 색을 씁니다. 항목 목록은 [비공식 정리본](https://a11ykr.github.io/kwcag22/) 기준이며, **인증을 받거나 전문가가 심사한 결과가 아닙니다.**

- 자동 검사: axe(스토리, E2E), 조작 영역 측정, 키보드 조작 E2E
- 수동 실행: Nu HTML Checker(마크업 검사). 2026-11-08 재디자인 후 26.11.4 버전을 로컬에서 실행해 다시 확인
- 재디자인 후 점검(2026-11-08): 세로 피드와 프로필 탭을 넣은 뒤 웹 20개 화면·상태를 라이트·다크, 320px·412px·1100px에서 axe, 가로 넘침, `h1`과 문서 제목, 조작 영역, Tab 30회 순회(초점 표시와 가림)로 확인하고, 나머지 항목은 코드와 화면으로 다시 판단했습니다. 위반은 없었고, 44px 미만으로 측정된 것은 가입 동의 문장 속 약관 링크뿐입니다. 점검 스크립트는 저장소에 없으며, 초점 가림과 조작 영역은 E2E에 있습니다.
- 하지 못한 것: 스크린 리더 실사용(VoiceOver, TalkBack), 공식 기준 수치와의 대조

| 결과 | 뜻 |

| 일부 | 대부분 확인했으나 빠진 부분이 있음 |

## 인식

| 항목 | 결과 | 근거 |
|---|---|---|
| 5.1.1 대체 텍스트 | 충족 | 게시 사진에 설명 입력, 없으면 작성자와 순서로 대체. 사진 뒤의 흐린 배경은 `alt=""`, 장식 아이콘은 `aria-hidden` |
| 5.2.1 자막 | 해당 없음 | 영상·음성 없음 |
| 5.3.1 표 구성 | 해당 없음 | 표 없음 |
| 5.3.2 선형구조 | 충족 | 헤더(로고, 테마, 글쓰기), 본문, 메뉴 순서. 피드 게시글은 화면에서 사진 위에 겹치지만 DOM은 작성자, 내용, 숫자, 사진, 동작, 댓글 입력 순이고, 앱은 같은 낭독 순서를 지정함. 넓은 화면의 왼쪽 메뉴는 DOM에서 본문 뒤 |
| 5.3.3 명확한 지시 | 충족 | 색이나 위치만으로 지시하지 않음 |
| 5.4.1 색 무관 인식 | 충족 | 좋아요는 채운 아이콘과 글자 굵기, `aria-pressed`, 현재 메뉴와 고른 탭은 글자 굵기와 `aria-current`·`aria-selected`(탭은 밑줄도 있음), 고른 관심사는 채운 모양, 본문 링크는 밑줄 |
| 5.4.2 자동 재생 금지 | 해당 없음 | 소리 없음 |
| 5.4.3 명도 대비 | 충족 | axe로 라이트·다크 20개 화면 확인. axe가 재지 못하는 사진 위 글자는 가장 불리한 흰 사진에 검정 70% 막을 올린 색(`#4d4d4d`) 기준으로 계산: 글자와 동작 아이콘 7.75:1, 공식 마크 3.5:1, 사진 번호 8.45:1. 보조 글자 5.82:1(라이트), 6.91:1(다크). 강조 파랑 위 글자 7.97:1(라이트), 5.92:1(다크). 입력칸 밑줄과 테마 스위치 테두리 3.32:1(라이트), 3.9:1(다크). 마우스를 올린 주요 버튼 13:1 이상 |
| 5.4.4 콘텐츠 구분 | 충족 | 구분선과 여백, 피드는 화면 한 장 단위로 구분. 구분선은 장식이라 대비 기준을 적용하지 않음 |

## 운용

| 항목 | 결과 | 근거 |
|---|---|---|
| 6.1.1 키보드 | 일부 | 20개 화면을 Tab으로 순회해 초점이 닿는 것을 확인. 메뉴, 신고 창, 사진 넘김, 하단 메뉴, 건너뛰기, 프로필 탭(방향키)은 실행까지 E2E로 확인. 피드의 스크롤 맞춤은 강제하지 않아 키보드로 스크롤을 막지 않음. 나머지 요소의 실행은 전부 확인하지 않음 |
| 6.1.2 초점 이동·표시 | 충족 | 초점 테두리, 밑줄형 입력칸은 밑줄을 1px에서 2px로 굵힘, 화면 이동 시 본문으로 초점 이동, 대화상자 초점 관리는 antd. 고정 헤더와 하단 메뉴에 초점이 가리지 않게 `scroll-padding`을 쓰고 E2E로 확인. 사진 위 넘김 버튼은 흰 테두리와 검은 그림자를 겹쳐 사진 색과 상관없이 표시 |
| 6.1.3 조작 가능 | 일부 | 20개 화면 44px 이상을 측정(프로필 탭은 42×24px이던 것을 고침). 공식 기준 수치와 대조 필요. 문장 속 링크는 측정에서 제외 |

| 6.2.1 응답시간 조절 | 일부 | 로그인은 자동 재발급. 메일 링크 30분, 소셜 추가 입력 30분은 연장 없이 다시 시작해야 함 |

| 6.3.1 깜빡임 | 충족 | 깜빡이는 콘텐츠 없음 |
| 6.4.1 반복 영역 건너뛰기 | 충족 | 본문 바로가기, E2E로 확인 |
| 6.4.2 제목 | 충족 | 20개 화면 모두 문서 제목과 `h1` 1개. 피드의 `h1`은 화면에 보이지 않고 낭독만 됨 |
| 6.4.3 링크 텍스트 | 충족 | 격자 링크는 게시글 내용으로, 피드의 `댓글 보기`는 작성자와 내용으로 구분되는 이름 제공 |

## 이해

| 항목 | 결과 | 근거 |
|---|---|---|
| 7.1.1 기본 언어 | 충족 | `lang="ko"` |
| 7.2.1 사용자 요구 실행 | 충족 | 초점이나 입력만으로 화면이 바뀌지 않음 |
| 7.2.2 찾기 쉬운 도움 | 일부 | 약관과 처리방침은 설정의 같은 위치. 데모는 문의 메일이 없어 문의 메뉴를 숨김 |
| 7.3.1 오류 정정 | 충족 | 칸 옆과 경고 영역에 안내, 입력값 유지 (단위 테스트). 이메일 형식이 틀리면 브라우저 기본 검증이 제출을 막아 다른 칸의 안내가 나오지 않던 문제를 `noValidate`로 고침 |
| 7.3.2 레이블 | 일부 | 모든 입력에 레이블이 있음. 댓글과 메시지 입력칸의 레이블은 낭독 전용이라, 화면에는 자리표시자와 옆의 버튼만 보임 |
| 7.3.3 접근 가능한 인증 | 충족 | 붙여넣기와 자동 완성 허용, 인지 시험 없음 |
| 7.3.4 반복 입력 | 충족 | 같은 절차에서 다시 입력하게 하지 않음. 비밀번호 확인은 보안상 예외 |
